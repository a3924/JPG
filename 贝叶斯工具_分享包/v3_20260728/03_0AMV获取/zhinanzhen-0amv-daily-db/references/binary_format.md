# 指南针 `Z_SK0AMV` 日线二进制格式

## 数据源

- 文件路径：`<指南针安装目录>\ANALYSE\Data\ChinaStk\Z_SK\day.vdat`
- 文件状态：软件运行时会被加 **Windows 独占锁**，必须完全关闭指南针后再读取。

## 文件级结构

`.vdat` 中包含多个指标/品种的日线数据。0AMV（活跃市值）的块以 8 字节 ASCII 代码标识开头：

```
5a 5f 53 4b 30 41 4d 56  = "Z_SK0AMV"
```

该标识后立即跟随 28 字节/条的日线记录。0AMV 在 `day.vdat` 中通常被切成多个约 **250 个交易日**的连续块，按时间顺序排列。

## 单条记录结构（28 字节）

| 偏移 | 类型 | 含义 | 备注 |
|------|------|------|------|
| 0 | int32 | 日期 | YYYYMMDD，例如 20250818 |
| 4 | float32 | 开 | 活跃市值，单位：亿元 |
| 8 | float32 | 高 | 同上 |
| 12 | float32 | 低 | 同上 |
| 16 | float32 | 收 | 同上 |
| 20 | float32 | 量 | 原始整数；`量(亿) = 原始值 / 1e8` |
| 24 | float32 | 额 | 原始整数；`额(亿元) = 原始值 / 1e8` |

所有字段均为小端序（Little Endian）。

## 如何识别有效块

由于 `Z_SK0AMV` 标识可能在文件其他位置出现（例如索引表），因此不能仅靠字符串位置判断块起点。稳健做法：

1. 用正则/字节搜索找到所有 `Z_SK0AMV` 偏移。
2. 对每个偏移，尝试从 `offset + 8`（或 `offset + 48`、`offset + 88` 等，如果块前有额外元数据）开始解析记录。
3. 如果连续解析到 ≥20 条有效记录，且满足以下条件，则视为有效数据块：
   - 日期字段在合理区间（1990~2027）。
   - 开、高、低、收均为正数，且 `低 <= 开 <= 高`、`低 <= 收 <= 高`。
   - 数值量级在 0AMV 合理范围（约 5 千 ~ 200 万亿元）。
4. 合并所有有效块，按日期排序并去重。

## 日期与排序

每条记录自带 YYYYMMDD 日期，无需像 `.min15` 分钟文件那样倒推交易日。合并后直接按日期排序即可。

## 数据范围（实测）

在已下载完整 0AMV 数据的指南针安装中，合并所有块后通常覆盖：

- 最早：约 2007-05-15
- 最新：指南针本地数据最新日期（通常为当天或最近交易日）
- 2015-01-01 至今：完整可用，约 2700+ 个交易日。

## 与 `.min15` 分钟文件的区别

- `.min15`（`Z_SK0AMV.min15`）的 magic 为 `SKXM`，12 字节头部 + 28 字节/记录，但只有记录 0 带真实日期，其余记录首字段为内部流水序号，且日期需要倒推重建。
- `.day.vdat` 的每条记录都自带真实日期，更适合做完整历史数据库。
